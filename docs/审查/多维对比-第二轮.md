## 测试案例（条文推演）

**用户问：**「这一局值使落在庚上，该怎么断？」

### 原始版（基线 SKILL.md）会怎样答（推演）
- 步骤 1 写「先读 knowledge/」，步骤 4 才写跨卡读 Ontology → 模型**可能**先搜「值使」「庚」类卡名，再决定断法；**不保证**先读 `_Ontology.md`。
- 路由表有「有无对应格 → §2.6/§6.1」，但未写成决策树强制项 → 有机会命中「奇仪值门／太白刑门」类挂接，也有机会就近借名（硬规矩 3 有字，但读序不稳时执行率下降）。
- 无输出四块 → **不保证**写卡名／节号／是否推断。

### 优化版（SKILL-improved.md）会怎样答（推演）
- 决策树第 1 类含「有无对应格／断局」→ **必须先读** `_Ontology.md`（§2.6／§6.1，并可能及 §3.2／§4.2）。
- 硬规矩 3 保留：无格说没有，不许借名；若挂到推断案例须标「推断」。
- 输出四块强制：结论 + 依据卡片 + 关系依据（节号）+ 不确定／推断。
- **推演结论：** 优化版在本案例上，「先读 Ontology」「标依据／推断」两条均可执行；基线版仅「鼓励」，不稳定。
